# Scan CV Algorithm Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the shared CV pipeline (deskew, line detection, checkbox detection) that turns a rendered scan bitmap into `DetectablePage.rects`-shaped candidates, plus the golden test corpus that lets sub-projects 2b (Python) and 3 (JS/OpenCV.js) verify they produce matching results.

**Architecture:** A pure function `detect_lines_and_boxes(bitmap, dpi) -> list[dict]` in a new `engine/scan_cv/` package (deliberately NOT inside `engine/detect/`, which is copied verbatim into the Pyodide browser build — this package depends on `opencv-python`, which cannot install under Pyodide, so it must never be imported by anything in `engine/detect/`). Internally: grayscale → denoise → deskew (detect + correct + retain the inverse transform) → adaptive threshold → Hough line detection → contour-based checkbox detection → map every coordinate back through the inverse rotation and the pixel→point scale factor.

**Tech Stack:** Python, `opencv-python` (new dependency, BSD license — permissive, consistent with `AUTOPILOT.md`'s licensing rule), `numpy` (already a transitive dependency via `pdfplumber`/`pypdfium2`).

**Spec:** `docs/superpowers/specs/2026-09-12-scan-cv-algorithm-design.md` (and the interface it builds on: `docs/superpowers/specs/2026-09-12-scan-detection-interface-design.md`)

## Global Constraints

- **Never import `engine/scan_cv/*` from `engine/detect/__init__.py` or `engine/detect/rules.py`.** Those two files are copied verbatim into the Pyodide browser build (`scripts/build_site.py`'s `ENGINE_FILES`), and `opencv-python` has no pure-Python wheel — it cannot install under Pyodide. This package is Python-CLI/local-only until sub-project 3 does a *separate*, JS-native reimplementation for the browser.
- **Fixed render resolution: 300 DPI.** `SCALE = 300 / 72 ≈ 4.166667` is the single conversion factor between PDF points and pixels, in both directions, everywhere in this pipeline.
- **Coordinate mapping order, applied to every detected point:** (1) `invertAffineTransform` of the deskew rotation matrix, (2) divide by `SCALE`. No other transform is ever applied — the render step itself already preserves pdfplumber's top-down, origin-at-page-top convention.
- **Line rects must match `rules.py`'s existing thin-ruling-line convention exactly:** vertical (`width < 3, height >= 5`), horizontal (`height < 3, width >= 5`), so `grid_cells()`/R5b/etc. read them with zero changes to `rules.py`.
- **Checkbox rects are always emitted as `fill=True, stroke=False`**, regardless of whether the source ink was solid or hollow — this is the documented convention from the spec that lets R18 read them without any `rules.py` change (see the spec's "Checkbox detection" section for the full reasoning, including why the "more correct" alternative — broadening R18 — is blocked on an unrelated ground-truth defect).
- **No changes to `engine/detect/rules.py` or `engine/detect/__init__.py`** anywhere in this plan.
- **New dependency:** add `opencv-python>=4.10` to `requirements.txt` under a comment noting the BSD license, per `AUTOPILOT.md`'s "Licensing matters now" rule.

```python
# eval/scan_cv/generate.py
"""Generates the golden corpus for engine/scan_cv's shared CV pipeline.

Run once, at dev time, whenever a fixture needs to change:
    .venv/bin/python -m eval.scan_cv.generate

Output is committed to eval/scan_cv/golden/ -- these are small, deterministic
PNGs, not the large real-scan corpus (which stays gitignored under
eval/corpus/). Both this project's Python implementation (sub-project 2b)
and a future JS/OpenCV.js implementation (sub-project 3) run their own
detection against these same static files and must match the recorded
expected output within a defined tolerance -- that comparison is what
actually verifies "matching quality" between the two, rather than shared
prose alone. See docs/superpowers/specs/2026-09-12-scan-cv-algorithm-design.md.
"""
import json
from pathlib import Path

import cv2
import numpy as np

DPI = 300
SCALE = DPI / 72.0
PAGE_W_PT, PAGE_H_PT = 200.0, 100.0
W, H = round(PAGE_W_PT * SCALE), round(PAGE_H_PT * SCALE)

OUT = Path(__file__).parent / "golden"


def _blank_page():
    return np.full((H, W, 3), 255, dtype=np.uint8)


def _draw_line(img, x0_pt, x1_pt, y_pt, thickness=2):
    cv2.line(img, (round(x0_pt * SCALE), round(y_pt * SCALE)),
              (round(x1_pt * SCALE), round(y_pt * SCALE)), (0, 0, 0), thickness)


def _draw_square(img, x0_pt, y0_pt, x1_pt, y1_pt, thickness=2):
    cv2.rectangle(img, (round(x0_pt * SCALE), round(y0_pt * SCALE)),
                  (round(x1_pt * SCALE), round(y1_pt * SCALE)), (0, 0, 0), thickness)


LINES_PT = [(10.0, 190.0, y) for y in (15.0, 35.0, 55.0, 75.0)]
CHECKBOX_PT = (10.0, 50.0, 30.0, 70.0)


def _lines_rects():
    return [
        {"x0": x0, "x1": x1, "top": y - 1, "bottom": y + 1,
         "width": x1 - x0, "height": 2.0, "fill": False, "stroke": True}
        for x0, x1, y in LINES_PT
    ]


def _checkbox_rects():
    x0, y0, x1, y1 = CHECKBOX_PT
    return [{"x0": x0, "x1": x1, "top": y0, "bottom": y1,
             "width": x1 - x0, "height": y1 - y0, "fill": True, "stroke": False}]


def generate():
    OUT.mkdir(parents=True, exist_ok=True)

    img1 = _blank_page()
    for x0, x1, y in LINES_PT:
        _draw_line(img1, x0, x1, y)
    cv2.imwrite(str(OUT / "fixture_lines.png"), img1)
    (OUT / "fixture_lines.json").write_text(
        json.dumps({"dpi": DPI, "rects": _lines_rects()}, indent=2))

    img2 = _blank_page()
    _draw_square(img2, *CHECKBOX_PT)
    cv2.imwrite(str(OUT / "fixture_checkbox.png"), img2)
    (OUT / "fixture_checkbox.json").write_text(
        json.dumps({"dpi": DPI, "rects": _checkbox_rects()}, indent=2))

    img3 = _blank_page()
    for x0, x1, y in LINES_PT:
        _draw_line(img3, x0, x1, y)
    _draw_square(img3, *CHECKBOX_PT)
    M = cv2.getRotationMatrix2D((W / 2.0, H / 2.0), 3.0, 1.0)
    img3 = cv2.warpAffine(img3, M, (W, H), borderValue=(255, 255, 255))
    cv2.imwrite(str(OUT / "fixture_rotated.png"), img3)
    (OUT / "fixture_rotated.json").write_text(json.dumps({
        "dpi": DPI, "true_skew_deg": 3.0,
        "rects": _lines_rects() + _checkbox_rects(),
    }, indent=2))


if __name__ == "__main__":
    generate()
    print(f"wrote golden corpus to {OUT}")
```

```python
# engine/scan_cv/preprocess.py
"""Grayscale + denoise + binarize a rendered scan bitmap.

Deliberately excludes deskew (see engine/scan_cv/deskew.py) -- this is the
standard, low-risk part of the pipeline; deskew is the part that needed
real iteration to get right during design.
"""
import cv2


def preprocess(bitmap):
    """bitmap: a BGR image (as cv2.imread returns). Returns a single-channel
    binary image (foreground=255, background=0), same pixel dimensions."""
    gray = cv2.cvtColor(bitmap, cv2.COLOR_BGR2GRAY)
    gray = cv2.medianBlur(gray, 3)
    binary = cv2.adaptiveThreshold(
        gray, 255, cv2.ADAPTIVE_THRESH_GAUSSIAN_C, cv2.THRESH_BINARY_INV,
        blockSize=25, C=10)
    return binary
```

### Task 3: Deskew detection and correction

**Files:**
- Create: `engine/scan_cv/deskew.py`
- Test: `tests/scan_cv/test_deskew.py`

**Interfaces:**
- Consumes: `preprocess()` from Task 2.
- Produces: `detect_skew_angle(binary) -> float` (degrees; the rotation to apply to straighten the image) and `deskew(binary) -> (numpy.ndarray, numpy.ndarray)` (the rotated image, and the 2x3 rotation matrix `M` used — callers need `M` to build `cv2.invertAffineTransform(M)` later, per the spec's coordinate-mapping chain). Tasks 4 and 5 both call `deskew()` and use the returned `M` to map their detections back to original-image pixel space before converting to PDF points.

**Design guidance from this plan's own verification work (a starting point, not a final answer — this is exactly the part the spec calls out as needing real iteration, not spec-time guessing):**
- A `minAreaRect`-based angle estimate was tried first and failed badly on a basic synthetic-rotation test (detected 34.2° on a true 3° rotation) — do not use this method.
- A projection-profile method (rotate candidate angles across a small search range, e.g. ±10° in ~0.2° steps, and pick the angle whose horizontal row-sum profile has the highest variance — sharpest peaks mean the most horizontal features are best aligned) correctly recovered the true angle (detected exactly -3.00° needed to correct a true +3.00° skew) on a page with multiple horizontal lines. This is the recommended starting point.
- When warping an already-binary image, use `flags=cv2.INTER_NEAREST` in `warpAffine`, not the default linear interpolation — linear interpolation on a binary image introduces gray fringe values that can distort downstream edge detection.
- A real failure mode was observed even with the above: with the fine-grained angle correction, the deskewed image's rotated line pixels can still show a staircase pattern that a subsequent Hough transform can misread as a diagonal line bridging between two DIFFERENT real horizontal lines, rather than following either one correctly. If this shows up in this task's own angle-only tests it does not block this task (Task 3 only tests the recovered ANGLE, not downstream line detection — that is Task 4's problem to solve, potentially by tightening the near-horizontal angle tolerance or the max line gap there). Flag it in this task's report either way so Task 4's implementer starts with the context.

```python
# engine/scan_cv/deskew.py
"""Detects and corrects page skew on a preprocessed (binary) scan image.

See docs/superpowers/specs/2026-09-12-scan-cv-algorithm-design.md's
"Pipeline architecture" section for why this step exists and what must
happen to detected coordinates afterward (the inverse-transform chain).
"""
import cv2


def detect_skew_angle(binary, search_deg=10.0, step_deg=0.2):
    """Returns the rotation angle (degrees) that straightens `binary`.

    Uses a projection-profile search: the correction angle is the one
    whose horizontal row-sum profile has the highest variance (sharpest
    peaks = most horizontal features best aligned). A minAreaRect-based
    approach was tried and rejected during design -- see this file's
    associated plan task for why.
    """
    h, w = binary.shape
    center = (w / 2.0, h / 2.0)
    best_angle, best_score = 0.0, -1.0
    angle = -search_deg
    while angle <= search_deg + 1e-9:
        M = cv2.getRotationMatrix2D(center, angle, 1.0)
        rotated = cv2.warpAffine(binary, M, (w, h), borderValue=0,
                                  flags=cv2.INTER_NEAREST)
        score = rotated.sum(axis=1).var()
        if score > best_score:
            best_score, best_angle = score, angle
        angle += step_deg
    return best_angle


def deskew(binary):
    """Returns (rotated_image, M) -- M is the 2x3 matrix used, so callers
    can later invert it via cv2.invertAffineTransform(M) to map detected
    coordinates back to the original (pre-deskew) pixel space."""
    h, w = binary.shape
    center = (w / 2.0, h / 2.0)
    angle = detect_skew_angle(binary)
    M = cv2.getRotationMatrix2D(center, angle, 1.0)
    rotated = cv2.warpAffine(binary, M, (w, h), borderValue=0,
                              flags=cv2.INTER_NEAREST)
    return rotated, M
```

### Task 4: Line detection → synthetic `rects`

**Files:**
- Create: `engine/scan_cv/lines.py`
- Test: `tests/scan_cv/test_lines.py`

**Interfaces:**
- Consumes: the ALREADY preprocessed-and-deskewed binary image and its rotation matrix — i.e. the output of `preprocess()` (Task 2) piped through `deskew()` (Task 3). This function does not call `preprocess`/`deskew` itself: Task 6 calls them exactly once per page and passes the result to both this function and Task 5's, so a page is never deskewed twice.
- Produces: `detect_lines(deskewed, M, dpi) -> list[dict]` — each dict is a `rects`-shaped entry (`x0, x1, top, bottom, width, height, fill: False, stroke: True`) in PDF points, matching `rules.py`'s existing thin-ruling-line convention (`height < 3, width >= 5` for a horizontal line — this task only needs the horizontal case; vertical write-on lines are visually rare enough on real scanned forms that they are out of scope for this first pass, and nothing here should special-case them prematurely). This is one of the two functions Task 6 combines into `detect_lines_and_boxes`.

**Design guidance:** a real failure mode was observed during design (see Task 3's notes): after deskewing, a Hough-detected "line" can bridge between two different real horizontal lines rather than following one correctly, especially with a generous `maxLineGap`. Tighten the near-horizontal angle tolerance and/or reduce `maxLineGap` if the fixture tests below show cross-line bridging (a detected line whose endpoints' y-coordinates don't both match one of the fixture's actual line y-values within tolerance).

```python
# engine/scan_cv/lines.py
"""Detects write-on lines / table rules and emits them as DetectablePage
rects, matching rules.py's existing thin-ruling-line convention exactly
(height<3, width>=5 for horizontal) so grid_cells()/R5b/etc. read them
with zero changes to rules.py.
"""
import cv2
import numpy as np

ANGLE_TOL_DEG = 3.0          # near-horizontal tolerance
MIN_LEN_FRACTION = 0.1       # of page width
MAX_LINE_GAP = 5             # px; see this task's design guidance on bridging


def detect_lines(deskewed, M, dpi):
    """deskewed: the binary, already-deskewed image (engine.scan_cv.deskew's
    output). M: the rotation matrix deskew() used, for mapping detections
    back to original pixel space. Callers get both from ONE preprocess()+
    deskew() call shared with detect_checkboxes -- see Task 6."""
    M_inv = cv2.invertAffineTransform(M)
    scale = dpi / 72.0

    h, w = deskewed.shape
    edges = cv2.Canny(deskewed, 50, 150)
    raw = cv2.HoughLinesP(edges, 1, np.pi / 180, threshold=30,
                            minLineLength=MIN_LEN_FRACTION * w,
                            maxLineGap=MAX_LINE_GAP)
    if raw is None:
        return []

    out = []
    for l in raw:
        x0, y0, x1, y1 = (l if l.ndim == 1 else l[0])
        angle = abs(np.degrees(np.arctan2(y1 - y0, x1 - x0)))
        if not (angle < ANGLE_TOL_DEG or angle > 180 - ANGLE_TOL_DEG):
            continue
        p0 = M_inv @ np.array([x0, y0, 1.0])
        p1 = M_inv @ np.array([x1, y1, 1.0])
        px0, px1 = sorted((p0[0], p1[0]))
        py = (p0[1] + p1[1]) / 2.0
        x0_pt, x1_pt, y_pt = px0 / scale, px1 / scale, py / scale
        out.append({
            "x0": x0_pt, "x1": x1_pt, "top": y_pt - 1.0, "bottom": y_pt + 1.0,
            "width": x1_pt - x0_pt, "height": 2.0,
            "fill": False, "stroke": True,
        })
    return out
```

```python
# engine/scan_cv/checkboxes.py
"""Detects checkbox-shaped squares and emits them as DetectablePage rects.

Always fill=True, stroke=False regardless of the source square's real
appearance -- see this plan's Global Constraints and
docs/superpowers/specs/2026-09-12-scan-cv-algorithm-design.md's "Checkbox
detection" section for why.
"""
import cv2
import numpy as np

CHK_MIN_PT, CHK_MAX_PT = 18.0, 32.0
SQUARE_TOL_PT = 8.0


def detect_checkboxes(deskewed, M, dpi):
    """deskewed: the binary, already-deskewed image (engine.scan_cv.deskew's
    output). M: the rotation matrix deskew() used. Callers get both from
    ONE preprocess()+deskew() call shared with detect_lines -- see Task 6."""
    M_inv = cv2.invertAffineTransform(M)
    scale = dpi / 72.0
    lo_px, hi_px = CHK_MIN_PT * scale, CHK_MAX_PT * scale
    tol_px = SQUARE_TOL_PT * scale

    contours, _ = cv2.findContours(deskewed, cv2.RETR_LIST, cv2.CHAIN_APPROX_SIMPLE)
    out = []
    for c in contours:
        peri = cv2.arcLength(c, True)
        approx = cv2.approxPolyDP(c, 0.02 * peri, True)
        if len(approx) != 4:
            continue
        x, y, w, h = cv2.boundingRect(approx)
        if not (lo_px <= w <= hi_px and lo_px <= h <= hi_px and abs(w - h) <= tol_px):
            continue
        p0 = M_inv @ np.array([x, y, 1.0])
        p1 = M_inv @ np.array([x + w, y + h, 1.0])
        x0_pt, y0_pt = p0[0] / scale, p0[1] / scale
        x1_pt, y1_pt = p1[0] / scale, p1[1] / scale
        out.append({
            "x0": x0_pt, "x1": x1_pt, "top": y0_pt, "bottom": y1_pt,
            "width": x1_pt - x0_pt, "height": y1_pt - y0_pt,
            "fill": True, "stroke": False,
        })
    return out
```

```python
# engine/scan_cv/pipeline.py
"""Public entry point for the shared scan-CV algorithm. See
docs/superpowers/specs/2026-09-12-scan-cv-algorithm-design.md.
"""
from engine.scan_cv.preprocess import preprocess
from engine.scan_cv.deskew import deskew
from engine.scan_cv.lines import detect_lines
from engine.scan_cv.checkboxes import detect_checkboxes


def detect_lines_and_boxes(bitmap, dpi):
    """bitmap: a BGR image (cv2.imread-shaped) rendered at `dpi`. Returns a
    list of DetectablePage.rects-shaped dicts in PDF points, combining
    line and checkbox candidates. Pure with respect to its inputs.

    preprocess()+deskew() run exactly once here and the result is shared
    with both detectors -- each independently re-running the deskew search
    (a ~100-iteration rotation loop) would double CV cost on every page for
    no benefit, since both detectors need the identical deskewed image and
    rotation matrix."""
    binary = preprocess(bitmap)
    deskewed, M = deskew(binary)
    return detect_lines(deskewed, M, dpi) + detect_checkboxes(deskewed, M, dpi)
```
